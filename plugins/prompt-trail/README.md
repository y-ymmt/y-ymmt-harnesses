# prompt-trail

> 帯を他のプラグインと共有したときの表示順の仕組みは、リポジトリ直下の README の「プロンプト上の帯の表示順」を参照。

このセッションで打ったプロンプトを、入力欄の上の帯に棒の列で（または会話の横のペインに 1 行ずつ）並べる
Claude Code プラグイン（function hooks）。棒にホバーするとそのプロンプトとターンの要約が読め、クリックで
会話のその位置へ飛ぶ。

**[prompt-rail](https://github.com/oikon48/prompt-rail)（作者 [oikon48](https://github.com/oikon48)、MIT ライセンス）を元にした改変版**で、
コミット `2ac50fb87fc426fed89ba0f09f1784ef6f289ae8`（prompt-rail 0.7.1、「Release 0.7.1 (#56)」）を取り込み、次の 6 つを足している。

1. 帯の並び順をこのリポジトリの他のプラグイン（tokyo-board・touch-tree・next-prompts）とそろえる
2. 日本語化（ボタン・トースト・コマンドの返事・`/config` の項目・ヘルプ）と、`find` の揺れを区別しない検索
3. 過去のプロンプトの再利用（`[ 入力欄へ ]` `[ コピー ]`）
4. ターンの結果を棒の色で出す（編集・失敗・拒否・中断・読むだけ・実行中）
5. セッションの途中で入れたときや、classic hook が届かない環境でも、トランスクリプトを見つけて会話の順に並べる
6. スラッシュコマンドの扱い（ターンが走るコマンドは棒に並べ、押すと描かれた行か返事の行へ飛ぶ）

```
       [ 入力欄へ ] [ コピー ] #13 ログイン画面のテストを直して · 1分23秒 · ツール 6 · 失敗 1 · 編集 2（login.ts…   ← ホバーした棒のカード
││││││││││││┃││││                                                                                         ← 棒（┃ が読んでいるプロンプト）
▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀                                                                                        ← ターンの結果の色（灰・緑・赤・紫・黄・青…）
─────────────────────
❯
```

カードのボタンは頭に置き、ホバーした棒（上では 13 番目、読んでいるプロンプトの `┃`）の真上に `[ 入力欄へ ]` のラベルの真ん中が
来るよう、左に空きを入れる。棒から指を真上に 1 行上げればボタンに届く。（上は形の説明。色は端末で確かめる。）

帯の右半分の棒（帯の幅の半分より右）では、カードを左へ伸ばす: `本文… · 補足 #94 [ 入力欄へ ] [ コピー ]`。`[ コピー ]` の右端が
棒の真上で終わり、本文は左の広い所に使える幅いっぱいで入る。棒が帯いっぱいに並んでも、右の方のカードの本文が読める。

## 入れ方

```sh
claude plugin marketplace add y-ymmt/y-ymmt-harnesses
claude plugin install prompt-trail@y-ymmt-harnesses
```

新しいセッションから出る。マウスで使うなら全画面表示（`"tui": "fullscreen"`）で使う。

### 本家 prompt-rail と同時に有効にしない

本家と同時に有効にすると、次のようにぶつかる（コードからの見立て。実機では試していない）。

- **帯**: 本家の横型は帯を自分の描画で置き換える（`next(e)` を呼ばない）。本家が外側に来ると、
  prompt-trail の棒も tokyo-board・touch-tree・next-prompts の行も消える。prompt-trail が外側なら、
  本家の棒の列は「約束を知らない描画」として帯のいちばん上に出て、棒の列が 2 本になる
- **ペイン**: 縦型では両方が自分のペイン（`prompt-rail` と `prompt-trail`）を開き、横の幅を取り合う
- **フォーカス**: 両方が読んでいる棒に `autoFocus` を付ける。ctrl+x tab の輪は先に描かれた方から始まる
- **読み込み**: 両方が同じトランスクリプトを読む（長いセッションでは `tail` も 2 本走る）
- **コマンド**: 名前が違うのでぶつからない（本家は `/prompt-rail`、こちらは `/prompt-trail`）

## 足した機能

### 1. 帯の並び順

帯を使う 4 つのプラグインは、同じ中身の `hooks/band.ts` の約束で自分の行を並び順つきの枠に入れて積み直す。
prompt-trail の行（カードの行・棒・色の帯）は `BAND_ORDER.promptTrail = 35` で、**天気・運行ボタン（30）と
次の一手（40）の間**に来る。読み込み順に関係なく、上から次の並びになる。

```
（天気・運行のボード）
[ touch-tree を開く ]
[ 天気・運行を表示 ]
#2 …カード…                ← prompt-trail
│┃│                         ← prompt-trail
▀▀▀                         ← prompt-trail
次の一手: [ 候補1 ] …
❯
```

本家は帯を置き換えていたので、ここだけ「先に `next(e)` で下の描画を受け取り、枠に入れて積み直す」形に変えた。
帯を出さないとき（off・アンケート中・サブエージェントの会話を表示中・プロンプトがまだ無い）は、下の描画をそのまま返す。

### 2. 日本語化と find の揺れ

- ボタン・トースト・コマンドの説明と返事・ペインの見出しと注記・ターンの要約（`1分23秒 · ツール 4 · 編集 2（a.ts, b.ts）`）・
  `/config` の項目（「表示の形」「ターンの結果で色分け」）を日本語にした
- コマンド名は本家とぶつからない `/prompt-trail`（とキー割り当て用の `/prompt-trail-next` `/prompt-trail-prev`）。
  サブコマンド（`horizontal` `next` `find` など）は本家のまま英語
- `/prompt-trail help` で使い方と色の凡例を出す
- `/prompt-trail find <語>` は、比べる前に両方を NFKC にし、小文字にし、カタカナをひらがなに寄せ、空白の続きを 1 つにする。
  全角/半角（`ＲＥＡＤＭＥ` と `readme`、`ﾃｽﾄ` と `テスト`）・大文字/小文字・ひらがな/カタカナ（`てすと` と `テスト`）を区別しない。
  `ｆｉｎｄ　語` のように全角で打っても通る。漢字の読みや表記揺れ（「確認」と「確かめ」）は区別する

### 3. 過去のプロンプトの再利用

| 場所 | 出し方 |
|---|---|
| 帯（横型）のホバーのカード | 左半分の棒: 頭に `[ 入力欄へ ]` `[ コピー ]`、その後ろに `#番号 本文 · ターンの要約`（右へ伸ばす）。ボタンはホバーした棒の真上に来るようにずらし、右寄りでも本文に 30 マス残す。右半分の棒（桁 × 2 ≧ 帯の幅）: `本文… · 要約 #番号 [ 入力欄へ ] [ コピー ]`（左へ伸ばす）で、`[ コピー ]` の右端が棒の真上。本文は棒の桁 - 23 - `#番号` の幅いっぱい（左へ伸ばすと本文が 30 マス取れない棒は右へ伸ばす）。帯が狭い（ボタン 24 マスと本文 30 マスが入らない）ときはボタンを出さない |
| 帯の棒をクリックしたあと | 会話のその位置へ飛び、そのカード（ボタンつき、ホバーのカードと同じ並び・位置）を 8 秒間、文字の行に残す |
| 縦のペイン | 読んでいる行の下（行を押したあとは 8 秒間その行の下）に `[ 入力欄へ ] [ コピー ]` の行。ホバーでは出し入れしない（下の行が動くため）ので、指の通り道の問題は無い。26 桁より狭いペインでは出さない（帯に出るカードはペインの外なのでボタンを置かない） |
| コマンド | `/prompt-trail fill [番号]`・`/prompt-trail copy [番号]`。番号を省くと読んでいるプロンプト（分からなければ最新） |

- **入力欄へ**: `$.prompt.fill({ text, mode: 'replace' })` で全文（改行も）を入力欄に入れる。送信はしない
  - 入力欄が空か、このセッションのプロンプトのどれかを入れたままなら、そのまま置き換える
  - 自分で打ちかけた文があるときは、1 回目は「入力欄に打ちかけの文があります。もう一度押すと置き換えます」と
    知らせるだけ。5 秒以内に**同じボタン**をもう一度押すと置き換える（next-prompts と同じ流儀）
  - ダイアログが開いているなど入力欄が受け取らないときは、そうトーストで言う
- **コピー**: `$.ui.copy` で全文をクリップボードへ入れ、「#3 をコピーしました」と出す
- ボタンを押しても会話の位置は動かない

**ホバーのカードが消えない仕組み（端末の帯）**: 棒ごとに key 付きの `Box`（棒と、その下の色の 1 マス）を作り、カードを
その `Box` の中に `position: "absolute"`（`top: -1` で文字の行へ、`left` で行の左端へ）で置く。カードには key を付けず、
`hover: { display: "flex" }` を scope 無しで付けるので、いちばん近い key 付きの `Box`（その棒の `Box`）にポインタがある間だけ出る。
型の説明のとおり、絶対配置の `Box` の上のポインタは親の上と数えられるので、棒から真上のカードへ指を上げても、カードの上を
左右に動かしても、ボタンの上でも、カードは出たまま。消えるのは、指がほかの棒（・その色の 1 マス）に乗ったとき（そのカードに
変わる）と、棒の `Box` とカードの外（帯の外・棒の列の右の空き）へ出たとき。

- ホバーで Mod のフックは動かない（surface が見た目だけを変える）ので、「数百 ms の猶予を置いてから消す」はできない
- 斜めに動かすと途中で隣の棒を通り、カードが隣のプロンプトに変わる（カードの `#番号` で分かる）。真上に上げてから横へ動かす

### 4. ターンの結果の色

各プロンプトの棒の真下に 1 マスの色（`▀`）を置く（縦のペインでは行の頭に `▌`）。
そのプロンプトが始めたターンで起きたことを、次の優先順で 1 つに決める（上ほど優先）。

| 色 | 種類 | 判定（トランスクリプトの行から） |
|---|---|---|
| 青 `#60a5fa` | 実行中 | そのターンがいま走っている |
| 紫 `#e879f9` | 拒否 | ツールの結果が拒否の文言（本人が No を選んだ `The user doesn't want to proceed…`・許可の設定で止められた `Permission to use … has been denied`・auto mode の判定 `Permission for this action was denied…`） |
| 黄 `#facc15` | 中断 | `[Request interrupted by user…]` の行がある（Esc で止めた）。記録にそのターンの終わり（`turn_duration` の行）がまだ無い間だけ、engine の知らせ（`turn.complete` の `reason: 'aborted'`）も使う |
| 赤 `#f87171` | 失敗 | ツールの結果が `is_error`（拒否を除く）か、API エラーで終わった |
| 緑 `#4ade80` | 編集 | `Edit` `MultiEdit` `Write` `NotebookEdit` を呼び、その結果が失敗・拒否でなかった |
| 灰 `#6b7280` | 読むだけ | 上のどれでもない（読む・調べる・答えるだけ） |

- **拒否を中断より上にした理由**: 本人が許可の確認で No を選ぶと、拒否の結果に続けて「中断」の行も書かれる。
  中断を上にすると、拒否が一度も色に出ない
- **失敗を編集より上にした理由**: 色は「確かめたほうがよいターン」を見つけるために使う。編集したかどうかはカードの
  `編集 N` でも分かる。`grep` が何も見つけずに終わった（終了コード 1）なども失敗に数えるので、赤は多めに出る
- 色の無いマス（空白）は、まだターンの記録が無いプロンプト（送ったばかり・トランスクリプトを読む前）
- ホバーのカードには、本家の「かかった時間・ツールの数・中断/API エラー」に加えて、**拒否されたツールの数**（`拒否 N`）・
  **失敗したツールの数**（`失敗 N`）・**編集したファイルの数**（`編集 N（ファイル名…）`）を出す。幅が足りないとファイル名から減らし、
  最後は `編集 N` だけ残す
- 情報源は本家と同じトランスクリプト（`.jsonl`）。ターンの終わり（Stop と `turn.complete`）で読み直すので、走っている間は「実行中」の
  色のままで、終わってから結果の色になる
- engine の知らせ（`turn.complete`）は「どのプロンプトのターンか」を推して当てるので、記録にそのターンの終わりがあれば記録を信じる。
  送ってすぐ取り消され、同じ文で送り直されたプロンプト（記録では本線から外れる）の「中断」が、送り直した方や 1 つ前のプロンプトに
  付くことがあったため（0.2.0 で直した）。打った文で始まったのにその文のプロンプトがまだ並んでいないターンの知らせは、どのプロンプトにも付けない
- `colors` をオフにすると色の帯も印も描かない（本家と同じ見た目）
- 凡例は `/prompt-trail help` にも出る

### 5. トランスクリプトの見つけ方

本家はトランスクリプトの場所を classic hook（`classic.SessionStart`・`classic.Stop` の `transcript_path`）からだけ受け取る。
次のときはそれが届かず、トランスクリプトを読めないまま、**描かれた行だけを描かれた順に**並べていた。上へスクロールすると古い行が
後から描かれるので、新しいプロンプトが左（小さい番号）、古いプロンプトが右に来る逆転が起き、ターンの要約も engine の知らせだけになる。

- セッションの途中でプラグインを入れた・有効にした（その読み込みでは `classic.SessionStart` がもう済んでいる）
- 管理された設定（managed settings）のある機械。組み込みのセキュリティのプラグインがユーザーのプラグインの `classic.*` を飛ばす
  （debug ログに `prompt-trail: classic.SessionStart bypassed by …`・`classic.Stop bypassed by …`）

そこで、`session.start` とターンの始め・終わり（`turn.start`・`turn.complete`）でも場所を求める。覚えた場所（`$.store` の
`transcript:<セッション id>`）が無ければ、Claude Code の置き場所の決まり（`<設定フォルダ>/projects/<始めたフォルダのパスの英数字以外を
- にした名前>/<セッション id>.jsonl`。設定フォルダは `CLAUDE_CONFIG_DIR`、無ければ `HOME`（Windows は `USERPROFILE`）の `.claude`）から
探し、見つけたら覚える。長いパスでフォルダ名が切られている場合は、名前の頭が合うフォルダの中を見る。`/clear` は `session.end`
（`reason: 'clear'`）でも並びを空にする。

### 6. スラッシュコマンドの扱い

モデルへの依頼になってターンが走るコマンド（スキル・プロンプト型のカスタムコマンド。`/code-review --comment`、`/notion:search 議事録`）は、
ほかのプロンプトと同じく棒として並べる。カードの本文は打ったコマンドの文で、色・時間・件数もそのターンのものが付く。
ターンが走らずその場で終わるコマンド（`/compact` `/plugin` `/reload-plugins` `/config`、Mod が登録したコマンドなど）は並べない。

- **記録ファイル（.jsonl）の行は、記録そのものの印で決める**: `<command-name>` の行がコマンドで、その直後に展開の行（`isMeta`）か
  assistant の返事が続けばターンが走る、`<local-command-stdout>` の行や system の `local_command` の行が続けば走らない。
  コマンドの一覧は見ないので、使ったあとでそのコマンドが消えても、あとから増えても、過去の行の判定は変わらない。
  印の無い `/` で始まる文（`/tmp のログを見て`）は、ふつうのプロンプト
- **コマンドの一覧（`$.command.list()`）は、画面に描かれた行（`UserMessage` の text が `/` で始まる）の判定にだけ使う**:
  記録の行との結び付けと、まだ記録に書かれていない仮の行。`/` のあとの最初の語（`plugin:name` 形式も、日本語名も）が一覧にあるときだけコマンド
- 一覧は、セッション開始・プラグインの再読み込み・プロンプトの送信・ターンの開始のたびに取り直し、一覧に無い `/名前` が描かれたときにも
  1 回取り直す（1.5 秒より近くは取り直さない）。途中で `.claude/commands/` に足したファイルや、Mod が登録・解除したコマンドにも追従する。
  取れないときは、`/名前` のあとが空白か行末なら（日本語名は拾えない）コマンドとみなす今までの判定に戻る
- **押したときの飛び先**: 記録のコマンドの行は画面に描かれないので、描かれている `❯ /code-review …` の行を、文と順番（同じ文の n 番目どうし）で
  記録の行に結び付けて、そこへ飛ぶ。結び付かないときは、そのコマンドの直後の返事の行へ。どちらも無理なら点線（飛べない）

## 本家から引き継いだ機能

- 横型（入力欄の上の帯）と縦型（会話の横のペイン）、`off`。設定 `mode` と `/prompt-trail <形>` で切り替える
- 棒の形: `┃` 読んでいるプロンプト（画面のいちばん上の行が属するもの）／`│` ほか／`┆` 飛べなかったプロンプト（`next` `prev` は飛ばす）。
  縦のペインでは `━` `─` `┄`
- プロンプトが帯に入りきらないときは、読んでいるものを中心に窓をずらし、`‹` `›` で隠れた側を示す
- ctrl+x tab で帯の棒に輪を移し、`←` `→` で動かすとそのカードを数秒出し、Enter で飛ぶ
- `/rewind` で捨てた枝は外し、`/compact` の前も残し、再開したセッションは前のプロンプトも並べる。4 MiB を超えるトランスクリプトは `tail` で続きから読む
- サブエージェントの会話を表示している間は並べない（飛べないため）
- デスクトップアプリでは、カードを棒の上の行に、読んでいるプロンプトを棒の横に出す（重ね描きしない）

## コマンド

| コマンド | |
|---|---|
| `/prompt-trail horizontal` | 入力欄の上の帯に棒の列で出す（既定） |
| `/prompt-trail vertical` | 会話の横のペインに 1 行ずつ出す |
| `/prompt-trail off` | 出さない |
| `/prompt-trail next` / `prev` | 次・前のプロンプトへ飛ぶ |
| `/prompt-trail first` / `last` | 最初・最新のプロンプトへ飛ぶ |
| `/prompt-trail 12`（`#12`） | 12 番目のプロンプトへ飛ぶ |
| `/prompt-trail find <語>` | 語を含む最新のプロンプトへ飛ぶ（揺れを区別しない） |
| `/prompt-trail fill [番号]` | そのプロンプトを入力欄に入れる（送信しない） |
| `/prompt-trail copy [番号]` | そのプロンプトをコピーする |
| `/prompt-trail help` | 使い方と色の凡例 |
| `/prompt-trail-next` / `/prompt-trail-prev` | 引数の無い版（キー割り当て用。ターン中も動く） |
| `/prompt-trail` | いまの形で開き直す |

キー割り当ての例（`~/.claude/keybindings.json`）:

```json
{
  "bindings": [
    { "context": "Chat", "bindings": { "ctrl+k": "command:prompt-trail-prev", "meta+j": "command:prompt-trail-next" } }
  ]
}
```

## 設定

`/config` のプラグインの項目。

| 項目 | 既定 | 内容 |
|---|---|---|
| 表示の形（`mode`） | `horizontal` | `horizontal` / `vertical` / `off`。`/prompt-trail <形>` で変えても保存される |
| ターンの結果で色分け（`colors`） | オン | 棒の下（縦のペインでは行の頭）にターンの結果の色を出す |

## 限界

- 本家と同じく、function hooks は早期公開の API で、Claude Code の版で変わることがある
- 帯は 3 行（カードの行・棒・色）を取る。本家より 1 行多い
- ホバーのカードにボタン（24 マス）と、棒の真上に寄せるための空きを置くので、カードの文字が本家より短く切れる（右半分の棒は左へ伸ばすので広い）
  （右寄りの棒ほど短い。下限 30 マス）
- トランスクリプトの置き場所の決まりは Claude Code の今の版のもの。決まりが変わると、classic hook が届かない環境では
  描かれた行だけを並べる（以前の動き）
- 「編集」はツールで編集したものだけ。Bash の `sed -i` や `>` で書き換えたものは数えない
- 「失敗」はツールの結果の `is_error` そのまま。`grep` の 0 件や `test` の偽も失敗に数える
- 拒否の見分けは Claude Code がトランスクリプトに書く英語の文言に頼っている。文言が変わると「失敗」に数える
- ctrl+x tab で帯に移ると、輪は読んでいるプロンプトの棒から始まる（本家と同じ）。同じ帯にある touch-tree・tokyo-board・
  next-prompts のボタンへは `←` `→` で移る
- 1 つの棒が 1 マスである前提で色を真下に揃えている。罫線（`│`）や `▀` を 2 桁で描く設定の端末ではずれる（推測）

- コマンドの行へ飛ぶ動き（描かれた行との結び付け・返事の行への切り替え）はテストの engine では確かめられない
  （Mod の `$.ui.scroll` に答えないため）。結び付けと飛び先の決め方は関数で試し、実際の飛びは画面で確かめる
- ターンが走るコマンドの見分けは、Claude Code の今の版が記録に書く並び（コマンドの行 → 展開の行 → 返事）に頼っている
- ほかのエージェントやセッションからの知らせ（`<agent-message>` / `<cross-session-message>` で始まる行）はプロンプトに数えない
- 実行中の `queued_command`（ターン中に打って届いたプロンプト）は記録に印が無いので、`/名前` のあとが空白か行末の文はコマンドとして並べない

## 動作環境と確かめた範囲

実機で確かめたのは macOS・端末 Orca・全画面表示・Claude Code 2.1.289 での**読み込みまで**（`claude -p --debug-file` で
admitted、`does not validate` なし）。帯・ペイン・ボタンの見た目と押し心地は、まだ実機で見ていない。言葉の意味と共通の注意は
[リポジトリ直下の README](../../README.md#動作環境と確かめた範囲) を参照。

| 環境 | 状態 | 補足 |
|---|---|---|
| macOS + Orca（全画面表示） | 未確認 | 読み込みは確認済み。棒・カード・色の帯・ボタンは偽の `$` のテスト（terminal）だけ |
| 全画面表示でない端末（main screen） | 未確認 | クリックは Mod に届かないので、ctrl+x tab で帯に移って `←` `→` と Enter で飛ぶ（本家の流儀）。入力欄へ・コピーは `/prompt-trail fill` `copy` で使う |

| 管理された設定のある機械 | 一部確認 | `claude -p --debug-file` で、`classic.*` が飛ばされること、そのときの置き場所の決まりのパス、13 MB のトランスクリプトを `tail` で 0.4 秒で読めることを確かめた。帯の見た目は未確認 |

| VS Code 拡張・モバイル | 未確認 | テストも無い |
| `claude -p`・SDK | 未対応 | 帯もペインも描かれない |
| 明るい背景の端末 | 未確認 | 色は中くらいの明るさを選んだが、明るい背景で見ていない |

- テスト（`tests/`）は `claude-code/testing` の偽の `$` で、帯の並び（4 つのプラグインの 24 通りの読み込み順）・入力欄へ/コピー・
  打ちかけの文の確認・検索の揺れ・色分けの判定と色・日本語の文言・カードの並びと置き方（ボタンが頭・棒の真上・棒の `Box` の中）・
  「中断」の付け先・途中で読み込まれたとき／classic hook が届かないときの並びを見ている

  （飛ぶ先を選ぶ `pickPrompt` は単体で見ている）

## 仕組み

```
.claude-plugin/plugin.json   manifest（userConfig・types）                 改変（名前・作者・日本語の項目・colors）
hooks/hooks.json             modules: ["./index.tsx"]                      本家のまま
hooks/index.tsx              フックと `$` を使う処理すべて                    改変（帯の積み直し・色・入力欄へ/コピー・日本語・find・トランスクリプトの見つけ方）
hooks/band.ts                帯の並び順の約束（4 プラグイン共通）             独自（tokyo-board などと同じ中身）
hooks/trail.ts               fold・色分けの判定と色・拒否の文言・ヘルプ        独自
types/index.d.ts             $.state の契約（prompt-trail.moved）            改変（名前だけ）
tests/upstream.test.tsx      本家のテスト（`test(` が 110 個）                  改変（下）
tests/trail.test.tsx         足した 5 つの機能と日本語化のテスト               独自
LICENSE                      本家の MIT ライセンス                             本家のまま
tsconfig.json                型の確認                                          独自（他のプラグインと同じ形）
```

本家のテスト（`tests/upstream.test.tsx`）に入れた変更:

- プラグイン名・コマンド名を `prompt-trail` に、英語の文言の期待値を日本語に
- ボタンの key は一覧の添字でなくプロンプトの ID（`jump-<ID>`）に変えたので、期待値の key を ID（描いた行の `requestId`）に
- 飛ぶボタン（`jump-*`）だけを数える（カードとペインに足したボタンを除く）
- 帯の幅を 80 から 104 に（カードのボタンのぶん。カードの文字の幅は本家と同じ 76 マス）
- 端末の帯のホバーのカードは棒の `Box`（`bar-<i>`）の中の key の無い `Box` になったので、`card-<i>` で探していた 2 件はそこから探す
- 帯がまず下の描画を受け取るようになったので、engine の空の帯の代わりが無かった 2 件に足した
- 本家の「色の印を描かない」テストは、`colors` をオフにしたときのテストにした
- 2.1.289 の型で通るように、`$.command.run` の呼び方・フックの返り値・`setTimeout` の宣言を直した（動きは同じ）
