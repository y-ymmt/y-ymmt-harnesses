# next-prompts

> 帯を他のプラグインと共有したときの表示順の仕組みは、リポジトリ直下の README の「プロンプト上の帯の表示順」を参照。


Claude Code が薄字で 1 つだけ出す「次に打ちそうなプロンプト」を、**複数の候補**にして
プロンプトのすぐ上に並べる Claude Code プラグイン（function hooks）。候補を押すとその文が
入力欄に入る（送信はしない。直してから Enter）。

```
次の一手: [ テストも追加して ] [ コミットして ] [ 差分を見せて ]
          [ 別の画面も確認して ]
［touch-tree を開く］
> _
```

## 動き

- **作るとき** — メインループのターンが答えて終わったとき（`turn.complete`、サブエージェントと
  中断・エラーで終わったターンは除く）。作っている間は `次の一手: 候補を考え中…` を薄字で出す
- **作り方** — 直近の会話（`$.session.messages()`）を `$.model.complete` で haiku に渡し、
  `{"kind": 種類, "text": 依頼文}` の JSON 配列で返させる。読めない返事は捨てて何も出さない
  - 軽い仕事なので `effort: 'low'` で頼む（対応しないモデルでは無視される）。かかった時間と
    入出力トークン数は、1 回ごとにデバッグログへ `haiku effort=low 1234ms in=… out=… answered …` の形で出す
  - 渡すのは**直近から遡って 24,000 文字まで**。ツールの入出力の中身は落とし、ツール名だけ
    `（使ったツール: Read×3, Edit）` の形で残す。`<system-reminder>` などの注記も落とす
  - 1 発言が長いときは、ユーザーは頭 1,200＋終わり 600 文字、Claude は頭 600＋終わり 2,000 文字に縮める
  - 依頼者の口調（日本語の短い依頼文、1 つ 40 文字以内）に合わせるよう頼む
- **似た候補を除く** — 言い回しだけ違う同じ依頼が並ばないよう、2 段で除く
  - モデルには候補ごとに種類（答える・進める・確かめる・直す・尋ねる・片付ける・別件）を付けさせ、
    同じ種類は 1 つだけ残す。除いても件数が足りるよう、`count` より 2 つ多く作らせる
  - 手元でも、同じ選択肢の番号を選んでいるもの（「1で実装して」と「1 番で進めて」）と、
    2 文字組の重なりが 6 割以上のものは、前にあるほうだけ残す。送信済みの直前の依頼に似たものも除く
- **標準の提案** — Claude Code 自身の提案（`prompt.suggest` の origin が `suggestion` のもの）が来たら、
  候補の先頭に足し、それに似た候補を除く。入力欄の薄字の提案はそのまま出る
- **再開したとき** — 作った候補は `$.store` に、会話のいまの位置の指紋（最後のユーザーの発言と
  Claude の返事の終わりのハッシュ。中身は保存しない）と一緒に保存する（直近 30 会話ぶん）。
  `claude -c` / `-r` / `/resume` で再開すると、最初の描画で指紋が同じものを読み戻して出す。
  モデルは呼ばない。会話が先に進んでいたら出さない
- **消すとき** — 次のターンが始まったとき（作りかけなら止めて結果を捨てる）と `/clear`
- **作業中・候補が無いとき** — 候補のボタンは出さず、行だけ残して薄字で `（作業中）` `候補を考え中…` `—` を出す。
  行が出たり消えたりすると、上に並ぶ切り替えボタンの位置が動くため
- **出さないとき** — アンケートが帯を使っているとき、terminal 以外の surface、`claude -p`
  （帯を描く端末が無いので haiku も呼ばない）

### 押したとき

`$.prompt.fill({ text, mode: 'replace' })` で全文を入力欄に入れる（ラベルが `…` で切れていても全文）。

| 入力欄 | 押すと |
|---|---|
| 空、または候補を入れたまま手を入れていない | そのまま入れる（候補どうしの入れ替えは 1 回で済む） |
| 自分で打ちかけた文がある | 1 回目は「入力中の文があります。もう一度押すと置き換えます」と知らせるだけ。5 秒以内に**同じボタン**をもう一度押すと置き換える |

`append` や `insert` は打ちかけの文と候補が混ざって意味の通らない依頼になりやすく、黙って
`replace` すると打った文が消えるので、2 回押しで確かめる形にしている。

### 帯の並び

候補の行は**入力バーのすぐ上（帯のいちばん下）**に置き、帯を使う他のプラグインの描画はその上に並べる。

```
（夕方などは天気・運行のボード）
[ touch-tree を開く ]
[ 天気・運行を表示 ]
次の一手: [ 候補1 ] [ 候補2 ] [ 候補3 ] [ 候補4 ]
──────────────────────
❯
```

3 つのプラグインは自分の行を並び順つきの枠に入れ、受け取った描画と合わせて `hooks/band.ts` の順に積み直す。
読み込み順がどうなっても、候補の行はいちばん下（入力欄のすぐ上）に来る。

## 設定

| キー | 既定 | 内容 |
|---|---|---|
| `enabled` | `true` | 候補を出す |
| `count` | `4` | 一度に並べる候補の数（3〜6、標準の提案を含む）。帯の幅で 2 行に収まらない分は出さない |
| `model` | `haiku` | 候補を作るモデル（エイリアスか完全な ID） |

## かかる量

1 回の候補づくりで、会話は最大 24,000 文字（日本語中心でおよそ 1.5〜2.5 万トークン）＋依頼文、
返事は 512 トークンまで（実際は 100 トークン前後）。haiku（入力 $1／出力 $5 per MTok）で
**1 回あたり最大 2〜3 セント、短い会話なら 1 セント未満**。ターンが答えて終わるたびに 1 回呼ぶ。
