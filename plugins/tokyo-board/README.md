# tokyo-board

プロンプトの上の帯に、**東京の天気**・**電光掲示板風の運行情報**・**株価**を出す
Claude Code プラグイン（function hooks）。3 面とも高さ 7 行で揃えてある。

```

│  ▄▄▄    ██ ▄█     13:09 │ ║ ■ 山手線        平常運転    13:09 ║ │ ▄█ ▀▀█ █▀█ █▀▀  円   │
│ ▟███▙   ▄█ ▀█▀ .1°C     │ ║ ■ 東急田園都市線  ◀ 車両故障の影響 ║ │  █ ▄▄█ █▀█ ▀▀█  ▲26  │
│▝▀▀▀▀▀▘  ██  █           │ ║ ▲ 大雨警報 雷注意報               ║ │ ▄█▄█▄▄ █▄█ ▄▄█ +2.07%│
```

## 何を出すか

### 天気パネル（26 × 7）
- **実況**は気象庁アメダスから。`latest_time.txt` で最新時刻を取り、
  `point/{地点}/{YYYYMMDD}_{HH}.json`（`HH` は 3 時間刻み）を読んで、いちばん新しい
  観測の **気温・湿度・前 1 時間降水** を出す。10 分ごとに更新される。
- **アイコン**は Open-Meteo の `current.weather_code`（WMO）を晴／曇／霧／雨／雪／
  にわか雨／雷に均したもの。空模様で枠の色も変わる（晴＝黄、雨＝青、雷＝紫）。
- 気温の整数部は七分割の大きい字（3 行）、小数と `°C` はふつうの字。
- いちばん下は**きょうの見通し** `降水90% ↑22 ↓20 没17:47`。降水確率は気象庁の
  府県天気予報（`forecast/{府県コード}.json` の 6 時間ごと。いまが入っている区切りを
  取る）、最高最低と日の入りは Open-Meteo の `daily`（天気コードと同じ 1 回の要求で
  まとめて取る）。26 セルに入らない値のときは `↑22°` → `↑22`、`日没` → `没` と
  短いほうへ落ちる。
- 見出しの行は**気象庁の東京の天気ページへのリンク**。

### 電光掲示板
- Yahoo!路線情報の運行情報ページ（`/diainfo/{id}/0`）から状況を読む。路線名 → id は
  関東エリアの一覧から引き、1 日覚えておく（引けなければ組み込みの表。山手線 21 /
  東急田園都市線 114）。
- 黒地に LED 風の字。**平常＝緑、異常＝橙**。左の ■ は路線カラー
  （山手線 `#9ACD32`、東急田園都市線 `#20A288`、それ以外は灰）。右端に取得時刻。
- **状況文は長短にかかわらず常に横スクロール**する。右から入って左へ抜け、また右から
  出てくる。全角は 2 セルぶん進むので、切れ目にかかる全角は出さずに桁を守る。
- 各行はその路線の Yahoo ページへのリンク。
- **平常 ↔ 異常が入れ替わった瞬間**だけ `$.ui.toast` で知らせる（ターン中でも鳴る）。
- 高さは**天気パネルと同じ 7 行**で固定。内訳は枠 2 行 + 中身 5 行で、中身は
  「路線 → ▲ → 空行 → NEWS」の順。路線を増やしても ▲ が出ても背は伸びない
  （入りきらない路線は出ない）。

### 電光掲示板の ▲ 行（警報・注意報と地震）
- **ふだんは出ない。** 異常があるときだけ、空行 1 つと入れ替わって出る
  （＝警報が出ても掲示板の背は伸びない）。
- **警報・注意報**は気象庁の `warning/{府県コード}.json`。`warningArea`（既定
  `130010` = 東京地方）の区域を見て、`解除` と「発表警報・注意報はなし」は捨てる。
  重い順（特別警報 → 警報 → 注意報）に並べ、色は **特別警報 `#FF3B30` /
  警報 `#FF9500` / 注意報 `#FFD60A`**。知らないコードは「その他の警報」として拾う
  （黙って消すと本物の警報を見落とすため）。
- **地震**は `quake/data/list.json`。同じ地震（`eid`）の速報と詳報をまとめ、
  **発生から `quakeWindowMin` 分（既定 60）以内**で、かつ
  **見ている都道府県で震度 1 以上**か**全国の最大震度が `5-` 以上**のときだけ出す。
  文は `地震 13:02 千葉県北西部 M5.2 最大震度5- 東京4`、色は赤。窓から出れば自然に消える。
- **トーストは警報・特別警報が新しく出たときと、条件に当たる地震だけ**。注意報は
  毎日のように出るので黙って出すだけにしてある。
- 行の頭の印は `▲`。`⚠`（U+26A0）は等幅フォントが持っていないことが多く、絵文字へ
  落ちると 2 セル幅になって掲示板の桁がずれるので使わない。
- 行は気象庁の警報ページへのリンク。

### ニュース行（複数の配信元＋キーワード絞り込み）
- 配信元は設定 `newsFeeds` に `;` 区切りで並べる。1 つは
  `ラベル|URL|キーワード,キーワード,…`（キーワードは省略可＝全部通す）。既定は
  **ITmedia AI＋ / ITmedia NEWS / NHK（Google ニュースの検索 RSS で `site:news.web.nhk` に AI・IT 語）**の 3 本。
  NHK には IT カテゴリの RSS が無く、IT・ネット一覧ページも一覧本体を内部 API（外部から 403）で
  読んでいるため、Google ニュース経由にしている。見出し末尾の「 - NHKニュース」は落とす。
- **RSS 2.0 と Atom のどちらも読める**（`<item><link>` と `<entry><link href>`）。
  Publickey のような Atom の配信元を後から足せる。
- キーワードは**見出しだけ**を見て、大文字小文字を無視した部分一致。
- 同じ見出しは配信元をまたいで 1 本にし（ITmedia NEWS と AI＋ は重なる）、
  **配信元を交互に**並べる（AI+ → IT → NHK → AI+ …）。本数は `newsCount`
  （**配信元 1 つあたり**。既定 3 なので 4 本で 9〜12 本）。
- 流す文は `[AI+] 見出し　◆　[IT] 見出し　◆　…`。行頭の固定ラベルは白太字の `NEWS`。
- **リンクは見出しごとに別々**。`marqueeRunsOf` が、流れている行を「いま窓に
  見えている見出しの断片」に切って返し（位置の決め方は `marqueeOf` と同じで、
  断片の字をつなぐと `marqueeOf` の返す文とちょうど一致する）、ニュース行だけは
  断片ごとに `<Link>` を張る。空白の断片と、窓の端で半分だけ欠けた全角にはリンクを
  張らない。見出しが 1 本も無ければ行ぜんぶがただの空白になる。
- 10 分ごとに**配信元ごとに独立して**取り、1 本落ちても残りはそのまま出る。
  NHK は新しい配信元が駄目なときだけ昔の `www.nhk.or.jp` を試す。

### 株価パネル（26 × 7・3 面目）
- Yahoo!ファイナンス（日本）の `quote/{code}.T` の HTML に埋まっている JSON
  （`"` が `\"` に逃がしてある）から `priceBoard` を読む。逃がしを戻してから
  名前で引いているだけなので、`始値` `高値` `安値` `出来高` `前日終値` も同じ要領で取れる。
  場前の `---` は null になる。
- **見出しは面を切り替えるボタン**。押すごとに
  **数字 → 1日 → 1か月 → 3か月 → 1年 → 5年 → 数字** と回る。ラベルは今の面の名前
  （端末では `[ 1か月 ]` と描かれる）。選んだ面は `$.store` に覚えるので次の起動でも
  そのまま。`hotkey` は付けていない（空のプロンプトで数字を打つと押されてしまう）。
  ボタンの前の銘柄名は銘柄ページへのリンクのまま。
- 押した中身は `ui.press` フックで進める。`onPress` は何もしない
  （`$` をトップレベル以外の関数に閉じ込めると `validate --strict` が嫌がるため）。

#### 数字の面
- 現在値は大きい字で **4 桁まで**。5 桁以上や取れないときは、ふつうの字で `12,345円`。
  右に `円` / 前日比 `▲26`・`▼26`・`±0` / 騰落率 `+2.07%`。
  色は**日本式で上げ＝赤 `#FF4D4D`、下げ＝緑 `#3DDC84`、変わらず＝灰**。
- 4 行目は**安値〜高値の棒**で、現在値の位置に `●`。安値＝高値や値が揃わないときは
  真ん中、範囲の外に出ている現在値は端に寄せる。
- 5 行目は始値・出来高（`23.8万株`）・取得時刻。

#### グラフの面
- 折れ線は**点字**（U+2800〜）。1 文字が横 2 × 縦 4 ドットなので
  **18 文字 × 4 行 = 36 × 16 ドット**。点字は幅 1 の BMP 文字なので `Text` に
  そのまま流せる（`Raster` は要らない）。右の 6 セルは上から
  高値・期間の頭・期間の末・安値。
- 隣り合う点の段差は縦に埋めて線をつなぐ。値の無い列（記録の無い時間）は空ける。
- 線の色は、**期間の最初より最新が上なら赤、下なら緑**。最下行は数字の面と同じ
  現在値・前日比・騰落率・取得時刻。
- **1日**は分足を配っているところが無いので、3 分ごとの株価取得を `$.store` に
  `{HH:MM, 値}` で当日ぶんだけ貯めて描く。横軸は 9:00〜15:30 で固定。
  点が 2 つに満たないうちは「3分ごとに記録します」と薄字で出す。
- **1か月**は `quote/{code}.T/history`（日足 20 行）、**3か月**は同じページの
  `?page=1..3`、**1年**は `timeFrame=w`（週足）、**5年**は `timeFrame=m`（月足）を
  3 ページずつ。その面を初めて開いたときに 1 回だけ取り、日付が変わるまで使い回す
  （`$.store` に期間ごとに残す）。途中のページで失敗したら取れたぶんで描く。
- 最新の点は現在値にする。日足の最終日がきょうなら置き換え、まだ前の営業日のままなら
  1 点足す。
- 取りにいくのは **平日 8:55〜15:35 JST のあいだだけ `stockRefreshSec` ごと**。
  それ以外は起動時の 1 回だけで、あとは終値をそのまま出す。判定は端末の時計の帯に
  依らないよう UTC から +9 時間して見る（祝日は見ない）。
- **横が足りないときはパネルごと出さない**（`bodyColumns` が `26×2 + 24 + 1×3` に
  届かないとき）。天気パネルと掲示板はそのまま残る。

## 取りにいく約束
- すべて `$.http.fetch`（プラグイン自身のネットワークではなく、ホスト経由）。
- **ターンが走っている間は取りにいかない**（`turn.start` 〜 `turn.complete`）。待機中だけ。
- 失敗したら前回値を出したまま、薄字で `取得できず HH:MM`。
- 既定の間隔は 天気 600 秒 / 運行 180 秒 / 警報・地震 300 秒 / ニュース 600 秒 /
  株価 180 秒（場中のみ）/ マーキー 250ms。マーキーは 4 回/秒なので
  `$.ui.invalidate` の上限（10/秒）には触れない。

## 帯の分け合い
この帯（`AbovePrompt`）は誰でも使える。本プラグインは **先に `next(e)` を呼び**、
下に居るもの（他のプラグインが描いたもの）を消さずに **自分のボードを上、相手を下**に
並べる。帯に入らない高さのときはボードを出さない。

## 表示する時間帯

既定では **17:00〜24:00 の間だけ**ボードを出す（定時前後に天気と運行を見る用途）。
時間帯の外では描画も通信もしない。30 秒ごとに出入りを見直し、入った瞬間に天気・運行・
警報・ニュースをまとめて取りにいく。作業中に入ったときは、ターンが終わった時点で取る。
テストは `bun test plugins/tokyo-board/tests/window.test.ts`。

## 隠す・表示する

プロンプトのすぐ上（帯のいちばん下）に **［天気・運行を隠す］／［天気・運行を表示］** を 1 つだけ固定で置く。
ボードの有無で位置が動かないので、続けて押して切り替えられる。時間に関係なく使える。

- 表示の時間帯（既定 17:00〜24:00）はボードを出す。押すと畳む
- 時間帯の外はボードを出さない。押すとその場で取りにいってボードを出す
- ボタンで変えた状態は覚えるが、時間帯へ出入りしたとき（17:00 と 24:00）にいつもの時間割へ戻す
- ボードを出していないあいだは、取得もマーキーも止める。帯を使う他のプラグインの描画はボタンの上に並べる

## 設定

`/plugin configure tokyo-board` または `/config` から。

| 項目 | 型 | 既定 | 何が変わるか |
|---|---|---|---|
| `enabled` | boolean | `true` | ボードを出すか |
| `showFrom` / `showUntil` | string | `17:00` / `24:00` | ボードを出す時間帯（PC の時計）。外では表示も取得もしない。同じ時刻か空なら終日。日をまたぐ指定も可 |
| `lines` | string | `山手線,東急田園都市線` | 見たい路線（カンマ区切り、6 本まで） |

| `weatherRefreshSec` | number (300〜3600) | `600` | 天気を取りにいく間隔 |
| `marqueeMs` | number (100〜2000) | `250` | 掲示板が 1 セル進むまで |
| `amedasPoint` | string | `44132` | アメダスの地点番号（既定は東京・大手町） |
| `latitude` / `longitude` | number | `35.6895` / `139.6917` | 天気アイコンと見通しを引く地点 |
| `warningArea` | string | `130010` | 警報・注意報を見る一次細分区域。降水確率もこの区域、地震は頭 2 桁の都道府県。例: `140010` 神奈川県東部、`270000` 大阪府 |
| `placeName` | string | `東京` | 天気パネルの見出しと震度の前に出す地名。`warningArea` に合わせて変える |
| `quakeWindowMin` | number (5〜1440) | `60` | 地震を ▲ 行に出しておく時間 |
| `alerts` | boolean | `true` | ▲ 行（警報・地震）を出すか |
| `news` | boolean | `true` | ニュースを流すか |
| `newsFeeds` | string | AI＋ / IT / NHK（Google ニュース検索） | `;` 区切りの `ラベル\|URL\|キーワード,…` |
| `newsFeed` | string | （空） | 旧設定。`newsFeeds` が空のときだけ 1 本として読む |
| `newsCount` | number (1〜15) | `3` | **配信元 1 つあたり**の見出しの本数 |
| `stock` | boolean | `true` | 株価パネルを出すか |
| `stockCode` | string | `7419` | 銘柄コード（既定はノジマ） |
| `stockRefreshSec` | number (60〜3600) | `180` | 場中に株価を取りにいく間隔 |

## 壊れたときの見分け方と直し方

Yahoo!路線情報は HTML を読んでいるので、**先方のページ構造が変われば壊れる**。
症状は決まっていて、**掲示板の行が前回の文のまま止まり、右下が `取得できず HH:MM` の
薄字になる**（落ちたりはしない）。そのときは:

1. `hooks/transit.ts` の `parseStatus` を見る。今は `id="mdServiceStatus"` の塊の中の
   `<dd class="normal|trouble">` と `<dt>` を読んでいる。`fixtures/` に平常と異常の
   実物を置いてあるので、新しい HTML を差し替えて `tests/transit.test.ts` を直せばよい。
2. 公式 API に移るなら **ODPT（公共交通オープンデータセンター）** が差し替え口になる。
   `hooks/transit.ts` の `parseStatus` / `lineIdOf` / `diainfoUrl` の 3 つだけが外と
   つながっているので、ここを ODPT の
   `https://api.odpt.org/api/v4/odpt:TrainInformation?odpt:operator=...&acl:consumerKey=...`
   に置き換えれば、`board.ts` から上はそのまま使える（要 API キー。`userConfig` に
   `sensitive: true` の項目を足して読む）。

Yahoo!ファイナンスも同じで、**`parseQuote` が null を返すと株価パネルは前回値のまま
薄字**になる。読んでいるのは `hooks/stock.ts` の `parseQuote` と `hooks/chart.ts` の
`parseHistory` の 2 つだけで、`fixtures/nojima-quote.html`（板）と
`fixtures/nojima-history.html`（日足）に実物を置いてある。埋め込み JSON の形が
変わったら、新しい HTML を差し替えて正規表現を直せばよい。時系列のページには
信用残の別表が同じ形で混ざっているので、**値が 8 つ以上ある行だけ**を日足として拾う
（5 つの行を取ると終値の位置に別の数が入ってグラフが跳ねる）。

気象庁と Open-Meteo と各社の RSS は JSON/XML なので壊れにくい。ニュースは
**配信元ごとに失敗を吸収**するので、1 本落ちても残りは出たままになる。NHK は
配信元が `www.nhk.or.jp` から `news.web.nhk` へ移った経緯があるので、
**新 → 旧の 2 段構え**にしてある。

## 中身

```
.claude-plugin/plugin.json   manifest（userConfig の宣言）
hooks/hooks.json             modules: ["./hooks.tsx"]
hooks/hooks.tsx              register()。タイマー・取得・描画
hooks/transit.ts             Yahoo!路線情報の読み取りと状態変化の検知
hooks/weather.ts             アメダスの時刻計算・実況・WMO コード・きょうの見通し
hooks/alerts.ts              気象庁の警報コード表・区域の読み取り・地震の選び方
hooks/news.ts                RSS/Atom の解析・絞り込み・交互並べ・見出しごとの断片
hooks/stock.ts               Yahoo!ファイナンスの板の読み取り・取引時間・レンジ棒
hooks/chart.ts               面の巡回・時系列の読み取り・点字の折れ線
hooks/board.ts               表示幅・マーキー・大きい数字・3 面の組み立て
fixtures/                    Yahoo（板・時系列）/ 気象庁 / ITmedia / NHK / Publickey の実物
tests/*.test.ts              claude-code/testing のテスト
tsconfig.json                JSX の factory（`h`）。bun でそのまま走らせるのに要る
```

`claude plugin test` は無いので、実際に走らせるテストは bun で回す:

```
cd plugins/tokyo-board
bun test <scratchpad>/mods-impl/tokyo.test.ts            # 読み取り・組み立て（25 本）
bun test <scratchpad>/mods-impl/smoke/aboveprompt.test.ts # 描画パスの煙試験（5 本）
```

煙試験は実物の fixtures を偽の `$.http.fetch` で食わせて `AbovePrompt` を 1 枚描き、
**props の型がエンジンの許す形か**まで見る。`color` に数値を渡すような間違いは木の
検証に落ちて帯が丸ごと消えるだけで何も言われないので、ここで捕まえる。

hook しているイベント（`claude plugin validate plugins/tokyo-board`）:

- `session.start` — タイマー 6 本（天気・運行・警報/地震・ニュース・株価・マーキー）を
  張り、1 度だけ取りにいく
- `turn.start` / `turn.complete` — ターン中は取りにいかない
- `ui.press{element=stock-face}` — 株価パネルの面を次へ進めて覚える
- `ui.render{component=AbovePrompt}` — ボードを描き、下に居るものをその下へ

## 使い方

`plugins/tokyo-board/` に置いてあるので、次にセッションを開いたときから
`tokyo-board@y-ymmt-harnesses` として自動で読み込まれる。今すぐなら `/reload-plugins`。
やめるときは `claude plugin disable tokyo-board@y-ymmt-harnesses`。
